# همراه سلامت خانواده

یک وب‌اپ کوچک فارسی برای ثبت دستی فشار خون و قند خون اعضای یک خانواده است. پروژه از نیاز واقعیِ نگهداری منظم اندازه‌گیری‌ها روی یک سرور شخصی شروع شده است: مدیر خانواده پروفایل می‌سازد و داده ثبت می‌کند؛ حساب پزشک همهٔ پروفایل‌ها را فقط می‌بیند و می‌تواند گزارش بگیرد.

این ابزار پروندهٔ پزشکی سازمانی یا ابزار تشخیص نیست. ثبت و مشاهده به اتصال به سرور نیاز دارد و دادهٔ سلامت نباید در مخزن عمومی قرار بگیرد.

## قابلیت‌های موجود

- پروفایل‌های جدا برای اعضای خانواده
- ثبت فشار خون در نوبت‌های یک یا دو قرائتی و ثبت قند در شرایط مختلف
- نمودار و دفتر سوابق با فیلتر بازه، نوع اندازه‌گیری و رکوردهای باطل‌شده
- خروجی CSV و گزارش چاپی که از پنجرهٔ مرورگر می‌توان به PDF ذخیره کرد
- نقش `admin` برای مدیریت و نقش `viewer` با نام کاربری پیش‌فرض `doctor` برای مشاهدهٔ همهٔ پروفایل‌ها
- manifest و service worker برای نصب پوستهٔ برنامه به‌صورت PWA؛ داده و API آفلاین cache نمی‌شوند

حساب عضو خانواده، ثبت‌نام عمومی، سطح دسترسی جداگانه برای هر پروفایل، ثبت آفلاین و تولید PDF سمت سرور در این نسخه وجود ندارد.

## فناوری و ساختار

پروژه build step یا وابستگی runtime خارجی ندارد: PHP 8.2/8.3، MySQL یا MariaDB، JavaScript و CSS خالص.

- `public/index.html` و `public/app.js`: رابط، مسیر انتخاب پروفایل تا ثبت و گزارش
- `public/api.php`: نشست، CSRF، نقش‌ها، اعتبارسنجی و تراکنش‌های دیتابیس
- `public/stats.js`: محاسبهٔ نوبت‌ها، آمار و جداسازی ردیف‌های هر پروفایل
- `private/schema.sql` و `private/install.php`: ساخت دیتابیس و دو حساب اولیه
- `public/manifest.webmanifest` و `public/sw.js`: نصب‌پذیری و cache پوستهٔ عمومی
- `tests/`: تست محاسبات و سناریوی یکپارچهٔ API روی دیتابیس آزمایشی خالی

تنظیمات در `private/config.php` قرار می‌گیرد؛ این فایل از `private/config.example.php` ساخته می‌شود و نباید commit شود. متغیر محیطی در کد فعلی استفاده نمی‌شود.

## اجرای محلی با دادهٔ ساختگی

پیش‌نیاز: PHP با افزونهٔ `pdo_mysql`، MySQL/MariaDB، و در صورت اجرای تست محاسبات Node.js.

1. یک دیتابیس و کاربر **صرفاً محلی و آزمایشی** با charset برابر `utf8mb4` بسازید.
2. `private/config.example.php` را به `private/config.php` کپی کنید؛ DSN و حساب همان دیتابیس آزمایشی را وارد و فقط برای loopback مقدار `https_only` را `false` کنید.
3. روی دیتابیس خالی نصب را اجرا کنید و رمزهای موقت چاپ‌شده را در password manager نگه دارید:

```bash
php private/install.php
```

4. برنامه را فقط روی loopback اجرا کنید:

```bash
php -S 127.0.0.1:8080 -t public
```

5. برای ساخت دادهٔ کاملاً ساختگی، بلافاصله پس از نصب و پیش از ثبت دستی اجرا کنید:

```bash
python3 tests/integration.py
```

آدرس `http://127.0.0.1:8080/`، عبارت `TEST` و رمزهای همان نصب آزمایشی خواسته می‌شود. اسکریپت اگر دیتابیس خالی نباشد متوقف می‌شود و پروفایل‌های «نمونه — سارا» و «نمونه — رضا» را می‌سازد. HTTP فقط برای `localhost`/loopback پذیرفته می‌شود؛ نصب واقعی باید HTTPS داشته باشد.

## دموی یک‌دقیقه‌ای

1. با `admin` وارد شوید و «نمونه — سارا» را انتخاب کنید.
2. در «ثبت اندازه‌گیری» یک فشار ساختگی ثبت کنید؛ پیام موفقیت فقط بعد از پاسخ سرور نشان داده می‌شود.
3. «دفتر ثبت و گزارش» را باز و عدد، تاریخ تهران و فیلترها را کنترل کنید.
4. «چاپ / ذخیره PDF» را بزنید و در پنجرهٔ مرورگر Save as PDF را انتخاب کنید. عنوان گزارش، نام پروفایل و فیلترهای فعال در نسخهٔ چاپی می‌آیند.

## تست و بررسی

```bash
node --check public/app.js
node --check public/stats.js
node --check public/sw.js
node tests/stats.test.cjs
python3 -m py_compile tests/integration.py
php -l public/api.php
php -l private/install.php
```

در بازبینی ۲۰۲۶-۱۱-۲۳، پنج دستور Node/Python بالا اجرا و موفق شدند. PHP و MySQL در محیط بازبینی نصب نبودند؛ بنابراین `php -l`، نصب دیتابیس، تست یکپارچهٔ API و خروجی واقعی PDF هنوز باید روی محیط محلی آزمایشی اجرا و با موبایل/مرورگر بررسی شوند.

## استقرار و محدودیت‌ها

در cPanel، فقط `public/` باید document root باشد و `private/` باید بیرون آن بماند. برای محیط واقعی `https_only` را `true` نگه دارید. نصب‌کننده برای دیتابیس خالی است و migration یا backup خودکار وجود ندارد؛ آن را روی دیتابیس دارای داده اجرا نکنید. فایل config، dump دیتابیس، log، PDF/CSV و تصویر حاوی اطلاعات سلامت را commit نکنید.

مدل دسترسی این نسخه عمداً خانوادگی و مشترک است: هر کاربر واردشده همهٔ پروفایل‌ها را از API دریافت می‌کند؛ فقط نقش `admin` می‌تواند پروفایل/اندازه‌گیری را تغییر دهد و `doctor` فقط مشاهده و خروجی دارد. اگر جداسازی داده بین کاربران یا پزشکان متعدد لازم است، مدل مجوز باید پیش از استفادهٔ عمومی بازطراحی شود.

جزئیات عملیاتی بیشتر و راهنمای اندازه‌گیری در [README فارسی قدیمی](README-fa.md) باقی مانده است.
